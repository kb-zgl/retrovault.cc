# i18n Multi-Language Support — RetroVault

**Date:** 2026-07-05
**Status:** Design Draft
**Target:** RetroVault (Nuxt 4 + Tailwind CSS v4 + Cloudflare)

---

## Context

RetroVault is a ~95% complete MVP with 2324 retro games, full emulator pipeline, and 8 pages. All UI text is hardcoded in English. Need to add multi-language support with minimal architectural disruption.

## Requirements

| Requirement | Decision |
|-------------|----------|
| Default language | English (en) |
| Target language | Simplified Chinese (zh) |
| Extensibility | Architecture must support adding more languages later |
| URL strategy | Sub-path prefix: en = no prefix, zh = `/zh/` |
| Translation scope | UI text only (nav, buttons, labels, footer, SEO meta, etc.) — game data stays English |
| SSR | Must work with Nuxt 4 SSR + Cloudflare edge |
| SEO | hreflang alternates, og:locale, per-language sitemap |

## Architecture

### Approach: Lightweight Custom i18n (no external dependencies)

Rejected `@nuxtjs/i18n` module due to:
- Compatibility uncertainty with Nuxt 4 (still RC)
- Overkill for 2 languages
- Known issues with edge deployments

### Data Flow

```
Request → middleware/locale.ts → detect locale → set useState('locale')
                                       ↓
                              Pages/Components → useI18n() → t('nav.games')
                                       ↓
                              locales/{en,zh}.json (lazy-loaded)
```

### Directory Structure

```
locales/
  en.json           # English translations (~80 keys)
  zh.json           # Simplified Chinese translations
composables/
  useI18n.ts        # Core i18n composable (SSR-safe, reactive)
middleware/
  locale.ts         # Route middleware for locale detection/routing
components/
  layout/
    LocaleSwitcher.vue   # Language switch dropdown
```

### URL Routing

| Language | Example URL |
|----------|-------------|
| English (default) | `retrovault.online/games` |
| Chinese | `retrovault.online/zh/games` |

- Default language (en) has **no URL prefix**
- Non-default languages use `/{lang}/` prefix
- Middleware strips prefix before page routing
- Cookie `locale` persists user preference
- First visit: browser language detection → auto-redirect if zh-CN

### 2. `useI18n` composable (`composables/useI18n.ts`)

```typescript
// SSR-safe reactive i18n composable
export function useI18n() {
  const locale = useState<string>('locale', () => 'en')
  const translations = useState<Record<string, any>>('translations', () => ({}))

  async function setLocale(lang: string): Promise<void> {
    locale.value = lang
    const data = await import(`~/locales/${lang}.json`)
    translations.value = data.default || data
    setCookie('locale', lang, { path: '/' })
  }

  function t(key: string, params?: Record<string, string | number>): string {
    const value = key.split('.').reduce((obj, k) => obj?.[k], translations.value)
    if (!value) return key  // fallback to key name
    if (!params) return String(value)
    return String(value).replace(/\{(\w+)\}/g, (_, k) => String(params[k] ?? ''))
  }

  // Load translation on mount if not loaded
  if (Object.keys(translations.value).length === 0) {
    // Will be pre-loaded by middleware, but handle edge cases
  }

  return { locale, t, setLocale }
}
```

**Key design decisions:**
- `useState` ensures SSR/client state consistency
- Dynamic `import()` for lazy loading per locale (code-split by Vite)
- Cookie for SSR persistence (middleware reads cookie)
- Fallback to key name if translation missing (visible = easy to spot)

### 3. Locale Middleware (`middleware/locale.ts`)

Global middleware running on every route:

```
1. Parse URL path for /{lang}/ prefix
2. If lang is valid (zh):
   a. Set locale useState to detected lang
   b. Strip /zh/ prefix, rewrite to internal route
   c. Load translation file
3. If no prefix:
   a. Check cookie 'locale'
   b. If no cookie, check Accept-Language header
   c. If browser is zh-CN → 301 redirect to /zh{path}
   d. Otherwise set locale = 'en'
4. Persist decision to cookie
```

**Edge cases:**
- `/zh` (bare) → redirect to `/zh` (implicit index/zh.vue route)
- API routes `/api/*` → skip middleware entirely (return immediately)
- Static files `/roms/*`, `/covers/*`, `/_nuxt/*` → skip middleware
- 404 pages → render in detected locale
- Route `/*` (all paths) — only first path segment checked for locale prefix

**Translation pre-loading flow:**
1. Middleware detects locale → calls `setLocale()` which lazy-imports the JSON
2. `useState('translations')` is populated before page renders
3. Components calling `useI18n()` find translations already loaded in state
4. On client-side locale switch, `setLocale()` loads new JSON and updates state
5. All `t()` calls reactively update as `translations` ref changes

### 4. Locale Switcher (`components/layout/LocaleSwitcher.vue`)

Minimal dropdown/button in header:

```
[🌐 EN ▼]
  ├─ English
  └─ 中文
```

- Each option navigates to the equivalent page in target language
- Uses `switchLocalePath()`-like logic: replace/prefix URL segment
- Visual indicator for current language (active state)
- SSR-compatible (no flash)

### 5. SEO Integration

Modify existing `usePageSeo` composable:

- Import `useI18n()` for translated strings
- `SITE_NAME` stays as 'RetroVault' (brand name, untranslated)
- `TAGLINE` pulls from translations: `t('seo.tagline')`
- OG type labels from translations: `t('seo.ogTypeHome')`
- Add `useHead` for hreflang alternate links on every page
- Set `og:locale` based on current locale

**hreflang implementation:**

```typescript
const route = useRoute()
const { locale } = useI18n()

// Strip /zh prefix for clean path
const currentPath = computed(() => {
  const path = route.fullPath
  return path.startsWith('/zh') ? path.slice(3) || '/' : path
})

useHead({
  link: computed(() => [
    { rel: 'alternate', hreflang: 'en', href: `https://retrovault.online${currentPath.value}` },
    { rel: 'alternate', hreflang: 'zh', href: `https://retrovault.online/zh${currentPath.value}` },
    { rel: 'alternate', hreflang: 'x-default', href: `https://retrovault.online${currentPath.value}` },
  ]),
})
```

### Type Safety Strategy

For a balance of safety and simplicity, use a **type helper** rather than full codegen:

```typescript
// types/i18n.ts
// Manual union type of all translation keys (maintained alongside JSON files)
type TranslationKey =
  | `nav.${'home' | 'games' | 'tags' | 'news' | 'about'}`
  | `hero.${'title' | 'sub' | 'count'}`
  | `game.${'playNow' | 'inQueue' | 'addQueue' | 'comments' | 'noComments' | 'post'}`
  | `footer.${'playersOnline' | 'login' | 'about' | 'privacy'}`
  | `common.${'loading' | 'error' | 'viewAll'}`
  | `seo.${'tagline' | 'ogTypeHome' | 'ogTypeCategory' | 'ogTypeDetail' | 'ogTypeBlog' | 'ogTypePage'}`

// t() overload accepting typed key
function t(key: TranslationKey, params?: Record<string, string | number>): string
```

This gives autocomplete in IDE without a build step. Add new keys to the type as translations grow.

## Key Constraints

1. **No breaking changes**: English locale must produce identical output to current code
2. **Lazy loading**: Translation files loaded on demand, not bundled
3. **SSR-first**: No layout shift from client-side hydration
4. **TypeScript**: Type-safe `t()` function (generated key type or typed wrapper)
5. **Edge compatible**: No Node.js specific APIs in translation loading
